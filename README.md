# naver-sheets-autofill

Daily / Monthly Keyword Calendar 자동 입력을 **이 PC 밖에서** 돌리기 위한 리포.

기존에는 작업 스케줄러 `NaverThemeDaily`(평일 20:10)가 헤드리스 `claude -p`를
띄우고, 그 세션이 크롬으로 구글시트를 열어 클립보드로 붙여넣었다. 그래서
**PC가 켜져 있어야만** 동작했고, 절전 중이면 작업이 PC를 깨웠다. 사용자가
"컴퓨터는 절전으로 두고 싶다"고 해서 GitHub Actions + Sheets API로 옮긴다.

## 지금 상태

**아직 실행되지 않는다.** 코드는 끝났고 로직 검증도 끝났지만, 구글 인증이
없어서 시트에 쓸 수 없다. 아래 "설정" 단계를 마쳐야 살아난다.
그때까지는 **로컬 `NaverThemeDaily`(20:10)를 끄지 말 것** — 그게 유일한 경로다.

| | 상태 |
|---|---|
| 테마 스캔 (`theme_scan.py`) | 동작 확인 (로컬 8.4초, 17개 테마 → 8개 그룹) |
| 지수 요약 (`market_summary.py`) | 기존 스크립트 그대로 |
| 네트워크 (GitHub 러너 → 네이버) | 실측 확인 — `finance.naver.com` 4개 경로 전부 200 |
| 행/열 계산 (`theme_write.py`) | `test_theme_write.py` 9건 통과 |
| 구글 시트 쓰기 | **미검증 — 인증 필요** |

## 설정 (사용자가 한 번만 하면 되는 부분)

1. <https://console.cloud.google.com/> 에서 프로젝트를 하나 만든다 (이름 아무거나).
2. **Google Sheets API**를 사용 설정한다:
   <https://console.cloud.google.com/apis/library/sheets.googleapis.com>
3. **IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기.** 역할은 주지 않아도 된다
   (권한은 시트 공유로만 준다). 만든 뒤 이메일 주소를 복사해 둔다 —
   `이름@프로젝트.iam.gserviceaccount.com` 형태다.
4. 그 서비스 계정의 **키 → 키 추가 → 새 키 만들기 → JSON**. 파일이 하나 받아진다.
5. 아래 두 시트를 **3번의 이메일 주소에 '편집자'로 공유**한다:
   - Daily Keyword Calendar `1xq_WNQh04xV1UsLm9ZRL6HhkQIJn-34G41zm87oR2h4`
   - Monthly Keyword Calendar `1OtZb8hDwb_vK1yGo6StT09jEUytXD9uoxB6Vxmq69ss`
6. 4번에서 받은 JSON 파일 **내용 전체**를 이 리포의 시크릿
   `GOOGLE_SERVICE_ACCOUNT_JSON` 에 넣는다:
   ```
   gh secret set GOOGLE_SERVICE_ACCOUNT_JSON < 받은키.json
   ```
7. `gh workflow run theme-calendar.yml` 로 수동 실행해서 확인한다.

**주의:** 서비스 계정은 사용자 본인 계정이 아니다. 5번의 공유를 하지 않으면
시트를 아예 못 본다 (권한 없음 오류). 반대로 공유한 시트에만 접근하므로
다른 문서가 노출되지는 않는다.

## 구조

```
theme_scan.py       finance.naver.com 테마 스캔(앞 2페이지) + 제외 + 병합
llm_group.py        오늘 테마를 Claude 가 묶고 제외 후보를 고른다
market_summary.py   코스피/코스닥 지수·거래대금·외인 -> stdout(JSON)
theme_write.py      두 달력 시트에 기록 (여기만 인증이 필요하다)
sheets.py           Sheets API 얇은 래퍼
keywords.json       키워드 그룹 정의 — 매 실행 llm_group 이 다시 쓴다
exclusions.json     스캔에서 뺄 테마·종목 — 사용자가 직접 고치는 파일
test_theme_scan.py  그룹 배정·제외 규칙 검증
test_llm_group.py   제외 기록 검증
test_theme_write.py 가짜 시트로 행/열 계산 검증 (인증 불필요)
cards.py            final_groups.json -> 스레드용 카드 PNG (1080x1350)
post_threads.py     카드를 스레드에 캐러셀로 게시
test_cards.py       카드 레이아웃을 원본 카드 실측값에 대조
feed_export.py      시트 내용을 아침 매수 후보 봇이 읽을 JSON 으로 내보낸다
codes.json          종목명 -> 종목코드 누적 지도 (시트에는 코드가 없다)
test_feed_export.py 내보내기 규칙 검증 (인증 불필요)
```

## 아침 매수 후보 봇에 시트를 넘긴다 (`feed_export.py`)

`volume-surge-telegram-bot/tradesignal` 은 07:30 KST 에 매수 후보를 고른다.
그 봇의 **테마·수급 신호는 이 시트에 적힌 것만** 센다.

전에는 그쪽이 네이버 테마 목록 API 를 따로 읽었는데 문턱이 여기와 달랐다 —
여기는 시총·등락률을 넘은 종목이 셋 이상인 테마만 싣고, 그쪽은 '테마 등락률
1% 이상, 오른 종목 3개 이상'이면 됐다. 그래서 2026-09-15 아침에 시트에 없는
'여행' 테마가 추천으로 나갔다. 기준이 둘이면 답도 둘이다.

```
theme-calendar.yml  시트 기록 → 되읽기 → theme_bot/feed/themes/<날짜>.json, latest.json
supply-demand.yml   시트 기록 →           theme_bot/feed/supply/<날짜>.json, latest.json
feed-republish.yml  (손으로만) 시트를 읽기만 해서 테마 피드를 다시 내보낸다
```

`feed-republish.yml` 이 따로 있는 이유: `theme-calendar.yml` 을 다시 돌리면
스캔부터 카드 렌더까지 다 하고 theme_bot 의 그날 카드 폴더를 갈아 끼우는데,
스레드에 이미 올라간 글이 그 이미지 URL 을 가리키고 있다. 피드 하나 만들자고
카드를 다시 그리게 둘 수 없다. 내보내기를 붙이기 전에 지나간 날을 메울 때,
사람이 시트 블록을 고친 뒤 봇에 반영할 때, 내보내기가 실패한 날을 다시 밀어
넣을 때 쓴다. 시트에 쓰지 않고 읽기만 한다.

봇 저장소에는 구글 인증이 없다. 그래서 카드가 이미 다니는 길(공개 저장소
`theme_bot`)로 같이 내보내고, 봇은 `raw.githubusercontent.com` 으로 받는다.
새 Secret 은 필요 없다 — 카드를 올릴 때 쓰는 `CARD_REPO_TOKEN` 그대로다.

**시트를 되읽어 내보낸다.** `final_groups.json` 을 그대로 보내면 사람이 시트를
손으로 고친 것이 빠진다. 시트가 기준이라고 해 놓고 시트를 안 읽으면 그 말이
아니게 된다.

### 종목코드 (`codes.json`)

시트에는 종목코드가 없다 — 사람이 읽는 표라 종목명·상승률·거래대금뿐이다.
그런데 봇은 일봉(거래량 배수·이동평균·신고가)을 받아야 하고 그러려면 코드가
있어야 한다. 코드를 아는 것은 스캔뿐이므로, 매 실행이 본 이름→코드를
`codes.json` 에 **덧붙이고 지우지 않는다**. 오늘 안 오른 종목도 어제 시트에는
올라 있을 수 있기 때문이다.

스캔이 0개인 날(시트에서 복원한 날)에도 어제까지 쌓인 지도로 코드가 붙는다.
그래도 못 찾은 종목은 버리지 않고 `missing_codes` 에 이름을 남긴다 — 봇이
그것을 알림 본문에 적으므로, 조용히 빠지는 일이 없다. 대개 사람이 블록에
손으로 적어 넣은 종목이 여기 걸린다.

### 수급 5일 창

수급동향 시트는 날짜 다섯 칸을 왼쪽으로 미는 창이다. 피드도 같은 창을 따라간다
— `merge_supply_window` 가 **시트에서 방금 읽은 날짜 줄**을 기준으로 남길 날을
정하므로, 사람이 시트를 손으로 밀었어도 다음 실행에 따라온다. 우리 파일이
아니라 시트가 창의 주인이다.

매일 도는 길은 창을 하루에 한 칸씩 채운다. 그 길을 붙이기 전에 지나간 날은
피드에 없는데 시트에는 있으므로, `feed_export.py supply-sheet` 가 시트를 읽어
그 칸을 되살린다(`feed-republish.yml` 의 `backfill_supply`).

시트에는 종목코드가 없어서 이름으로 맞춘다. `codes.json` 이 2,324종목을 들고
있어 2026-09-15 실측으로 수급 상위 74종목 중 59개가 맞았고, 못 맞춘 15개는
전부 ETF(KODEX·TIGER)였다 — 봇이 추천할 대상이 아니라 빠져도 손해가 없다.
개별 종목은 전부 맞았고 코드가 틀린 것은 0건이었다.

**이미 있는 날은 건드리지 않는다.** 순매수 API 가 준 날은 코드가 응답에 직접
들어 있어 이름으로 맞출 일이 없고 ETF 도 빠지지 않는다. 그쪽이 더 정확하므로
되살리기는 피드에 아예 없는 날만 메운다.

## 카드 봇 (`cards.py` / `post_threads.py`)

예전 카드 봇은 사용자 PC 안에만 있었다. 그 PC 가 그래픽카드 고장으로 켜지지
않게 되면서 **코드가 통째로 사라졌다** — `theme_bot` 리포에는 결과 PNG 만
올라와 있었고, 드라이브에도 백업이 없었다. 그래서 남아 있는 2026-09-04/07/08
카드를 픽셀 단위로 재서 다시 만들었다. 색·여백·행 간격·글자 크기는 전부 그
이미지에서 뽑은 값이고, `test_cards.py` 가 매 실행 그 좌표에 대조한다.

이제 PC 와 무관하게 GitHub Actions 에서 돈다. 시트를 쓴 다음 이어서:

```
final_groups.json + market_summary.json
  -> cards.py        01_monthly.png + 테마별 카드 (거래대금 순)
  -> theme_bot 리포   공개 URL 확보 (raw.githubusercontent.com)
  -> post_threads.py  캐러셀 한 건으로 게시
```

카드는 시트를 읽지 않고 `final_groups.json` 에서 직접 그린다. 시트 쓰기가
실패한 날에도 카드는 나가고, 둘이 같은 원본을 쓰므로 숫자가 어긋날 일이 없다.
평균상승률·거래대금의 정의는 시트 대표행의 `AVERAGEA`/`SUM` 과 같다.

**`theme_bot` 이 public 인 이유**는 스레드 API 가 이미지 업로드를 받지 않고
공개 URL 을 가져가기 때문이다. 그 리포는 코드가 없는 순수 이미지 호스트다.

### 필요한 시크릿 (셋 다 없어도 파이프라인은 안 죽는다)

| 시크릿 | 없으면 | 만드는 법 |
|---|---|---|
| `CARD_REPO_TOKEN` | 카드를 공개 리포에 안 올림 (실행 아티팩트에는 남음) | GitHub → Settings → Developer settings → Personal access tokens → Fine-grained. `theme_bot` 리포에 **Contents: Read and write** 만 준다 |
| `THREADS_USER_ID` | 게시 건너뜀 | 아래 참조 |
| `THREADS_ACCESS_TOKEN` | 게시 건너뜀 | 아래 참조 |

스레드 토큰은 <https://developers.facebook.com/> 에서 앱을 만들고 **Threads API**
제품을 추가한 뒤, `threads_basic` + `threads_content_publish` 권한으로 받는다.
받은 단기 토큰은 장기 토큰(60일)으로 교환해 둘 것 — 짧은 토큰을 넣으면 하루
이틀 뒤 조용히 게시가 멈춘다. `THREADS_USER_ID` 는 `GET
https://graph.threads.net/v1.0/me?fields=id&access_token=...` 로 확인한다.

**토큰은 60일마다 만료된다.** 만료돼도 카드는 계속 리포에 쌓이고 게시만
멈추며, 실행 로그에 `[threads] 게시 건너뜀` 이 남는다.

## 낡은 테마와 안 맞는 종목 (`exclusions.json`)

네이버의 테마 목록은 한 번 만들어지면 지워지지 않는다. `일본 수출규제`(2019년
한일 무역분쟁), `5G`(2019~2020년 상용화) 같은 옛 이벤트 테마가 그대로 남아
있고, 그 안의 종목이 오늘 각자의 이유로 오르면 옛 이름이 하루의 슬롯을
차지한다. 테마의 종목 구성도 같이 낡는다 — 통신 사업이 주력이 아닌 회사가
통신 테마에 남아 있고(피노), 수소 회사가 조선기자재에 들어 있다(범한퓨얼셀).

세 겹으로 거른다.

1. **제외 목록** `exclusions.json`. 테마명으로도, 시트에 뜨는 **키워드**로도
   지목할 수 있다. 패턴은 전부 **부분 문자열**이라 `일본 수출규제` 가
   `일본 수출규제(국산화)` 를, `반도체 장비` 가 `반도체 장비·소재` 를 잡는다
   — 정식 표기를 정확히 옮겨 적지 않아도 된다.

   ```json
   {
     "themes":   [{"pattern": "5G", "reason": "2019~2020년 테마", "by": "user"}],
     "keywords": [{"keyword": "환율하락 수혜", "reason": "테마가 아니라 분류다"}],
     "stocks":   [{"name": "범한퓨얼셀", "keywords": ["조선기자재"],
                   "reason": "수소 쪽", "by": "user"}]
   }
   ```

   - `themes` — 네이버 테마명으로 통째 제외.
   - `keywords` — 그 키워드에 묶인 테마를 전부 제외. 시트에는 테마명이 아니라
     키워드가 뜨니, 보고 나서 "이건 빼" 하게 되는 단위가 이쪽이다.
   - `stocks` — 종목 제외. `themes` / `keywords` 로 범위를 좁히면 **거기서만**
     빠진다. 범한퓨얼셀은 조선기자재에 있을 이유가 없지만 연료전지 테마에서는
     대표종목이 맞다. 둘 다 안 적으면 전역 제외이고, `code` 를 적으면 종목명
     대신 코드로 맞춘다(동명이인 방지).

   키워드는 매일 모델이 새로 짓는 이름이라 테마명보다 덜 안정적이다. 오래
   갈 제외는 테마명 쪽이 안전하고, 키워드는 "지금 이 묶음이 싫다" 에 쓴다.
   제외가 지목한 키워드는 `llm_group.py` 가 지도를 지우지 않고 살려둔다 —
   안 그러면 다음 실행에 그 키워드가 사라져 제외가 조용히 풀린다.

2. **참여율.** 구성종목 40개 중 3개만 오른 테마는 테마가 움직인 게 아니라
   그 3개가 움직인 것이다. 낡고 비대한 테마가 정확히 이 모양이라, 이름을
   목록에 적어두지 않아도 여기서 걸린다 (`MIN_PARTICIPATION` = 20%,
   `PARTICIPATION_RATE` = 3%). 작고 뜨거운 테마는 비율이 높아 남는다.

3. **모델 제안.** `llm_group.py` 가 그룹을 묶으면서 옛 테마·안 맞는 종목
   후보를 함께 고르고 `exclusions.json` 에 **덧붙인다**. 사람이 적은 항목은
   건드리지 않고, 사람이 지운 항목은 지워진 채로 둔다. 한 번에 오늘 테마의
   1/3 을 넘게 지우자고 하면 판단이 아니라 오작동으로 보고 통째로 버린다.

제외는 전부 실행 로그에 `[제외]` 로 남는다. 시트가 얇아 보이면 거기부터
보면 된다. `raw_scan.json` 은 **거르기 전**을 담으므로 무엇이 지워졌는지
나중에도 확인할 수 있다.

`keywords.json` 은 예전에 `C:\Users\USER\Desktop\클로드\키워드.json` 에 있던
파일이다. 러너는 그 경로를 볼 수 없으므로 리포 안으로 옮겼다. 지금은 **매
실행 `llm_group.py` 가 그날의 그룹으로 다시 쓰므로** 손으로 고쳐도 하루짜리다.
오래 가야 하는 교정 — 이 테마는 이제 안 본다, 이 종목은 이 테마가 아니다 —
은 `exclusions.json` 에 적는다 (GitHub 웹에서 바로 편집해도 되고, 로컬에서
고쳐 push해도 된다).

## 안전장치

시트를 잘못 건드리느니 아무것도 안 하는 쪽을 택한다. 다음이면 한 칸도 쓰지 않고 중단한다.

- 오늘 날짜 블록을 A열에서 못 찾음 (그 주 블록이 아직 안 만들어짐)
- 같은 날짜가 두 곳 이상 (어느 블록인지 확정 불가)
- 헤더행에 `종목명` 이 없음 (블록 구조가 예상과 다름)
- 대표행에 `AVERAGEA`/`SUM` 수식이 없음 (템플릿 미준비)
- 스캔 결과 그룹이 0개
- 주말

이미 오늘 것이 채워져 있으면 덮어쓰지 않고 건너뛴다. 그래서 로컬 20:10 작업과
같은 날 둘 다 돌아도 뒤에 오는 쪽이 앞의 결과를 뭉개지 않는다.

대표행의 상승률/거래대금 칸에는 `AVERAGEA`/`SUM` 수식이 들어 있고, 어떤 쓰기
범위에도 그 두 칸은 포함되지 않는다 (`test_theme_write.py` 가 검증한다).

## 알려진 한계

- **GitHub 예약 실행은 많이 밀린다.** 같은 계정의 `industry-report` 리포에서
  cron `0 8` 로 잡은 5회 실행이 전부 113~141분 늦게 시작했고, 8/27은 통째로
  건너뛰었다. 그래서 여기 cron은 정시를 피해 `13 11`(20:13 KST)로 잡았지만,
  이걸로 충분한지는 아직 증명되지 않았다. 저녁 작업이라 2시간 지연은 무해하고
  하루 통째 누락이 진짜 위험이다.
- 60일간 리포에 활동이 없으면 GitHub가 예약 워크플로를 자동 비활성화한다.
- 월간 시트 탭은 분기별이다. 분기가 바뀌면 새 탭이 필요한데 **탭 생성은
  자동화하지 않았다** — 못 찾으면 중단하고 사람을 기다린다.
- 슬롯(6개)보다 그룹이 많으면 뒤쪽을 버린다. 슬롯을 늘리는 건 수동 작업이다.
- **테마 목록은 앞 2페이지(약 80개)만 읽는다.** 목록이 전일대비 등락률
  내림차순이라는 데 기대는 선택이다. 뒤쪽 186개는 대개 옛 테마이거나
  구성종목 몇 개만 각자 오른 것들이라 어차피 걸러지고, 상세 요청이 ~270번에서
  ~82번으로 준다. 네이버가 정렬을 바꾸면 조용히 엉뚱한 80개를 보게 되므로,
  시트가 이상하면 `SCAN_PAGES` 를 7로 올려 비교해 볼 것.
- 참여율 문턱(20%)은 실측이 아니라 추정으로 잡았다. 몇 주 로그의 `[제외]`
  줄을 보고 조정할 것 — 너무 세면 진짜 테마가 빠지고, 너무 느슨하면 옛
  테마가 목록에 적힐 때까지 계속 올라온다.
- `keywords.json` 은 매 실행 통째로 다시 쓰인다. 여기 손으로 적은 그룹은
  다음 실행에 사라진다. 오래 가야 하는 판단은 `exclusions.json` 에 적을 것.
- 카드 글꼴이 원본과 다르다. 원본은 Pretendard 계열로 보이는데 러너에서
  받을 수 있는 건 Noto Sans CJK 라, 줄 위치와 높이는 같지만 글자 폭이 3~5%
  좁다. 똑같이 맞추려면 폰트 파일을 리포에 넣어야 한다(라이선스 확인 필요).
- 스레드 장기 토큰은 60일이다. 갱신을 자동화하지 않았다 — 만료되면 게시만
  조용히 멈추므로, 두 달에 한 번 로그를 보거나 토큰을 새로 넣어야 한다.
- `supply_demand.py` 는 예약 실행되지 않는다. 수급동향 시트는 별도의 Apps
  Script 가 담당한다 — 파일 안 설명 참조.
